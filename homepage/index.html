Betting Feature Store

Apache Flink + Apache Fluss · a real-time feature store

A sports-betting platform that is already trading: bets, settlements and logins stream into Kafka, players and wallets change in PostgreSQL. Seven Flink SQL jobs turn them into one feature row per player in a Fluss primary-key table, and every new bet looks that row up the moment it arrives, is scored by risk rules, and alerts land in PostgreSQL and Grafana.

Start here: the Pipeline Builder The architecture as buttons — create each table, deploy each job, watch the boxes go live. Or write the SQL yourself in the editor; both share one session that survives a reload.

The steps

  1. Declare the sources The fluss catalog, two postgres-cdc tables and the Kafka topics. flink_sql/01_sources_and_catalogs.sql
  2. Create the online feature store One Fluss primary-key table, one row per player. flink_sql/02_fluss_feature_store.sql
  3. Fill it Job A streams the dimensions from PostgreSQL; B1–D compute windowed and pattern features, each into its own columns. flink_sql/03_cdc_dimensions.sql, flink_sql/04_feature_calculations.sql
  4. Score every bet A lookup join FOR SYSTEM_TIME AS OF proc_time into Fluss, rules, the risk_scores topic, then the alerts to PostgreSQL. flink_sql/05_risk_scoring_inference.sql
  5. Fire an outlier and look The outlier generator, the inference API, Grafana, and the ad hoc queries. flink_sql/06_analytics_and_monitoring.sql
